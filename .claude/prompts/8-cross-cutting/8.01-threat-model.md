# Prompt: STRIDE Threat Model

## Goal
Produce `docs/security/threat-model.md`.

## Constraints
- Scope: web UI, API, worker, CFN execution, cross-account STS, GitHub App, CodeBuild,
  observability plane.
- Data flow diagram with trust boundaries: Internet/Edge, Platform Account, Target Accounts,
  GitHub, Observability plane.
- STRIDE table: 3+ threats per category. Per threat: affected component, attacker assumption,
  mitigation, residual risk, owner.
- Top 10 threats ranked by likelihood × impact.
- Include observability-specific threats: signed URL leakage, Loki log injection, Prometheus
  query DoS.
- Include template-sync threats: malicious template, path traversal, oversized tarball,
  credential theft.

## Acceptance
Security engineer signs off OR lists specific gaps for the next iteration.

## Enhancements (v2.1)
- Add the platform's **sharpest threat explicitly**: a malicious-but-validated template
  (cfn-nag-clean CFN can still create a role, exfiltrate via Lambda, etc.) — mitigations are the
  execution-role minimum + permissions boundary (3.6/6.7) + human review of new templates; state
  the residual risk honestly.
- Add insider/approver collusion and the "approve own request" bypass class.
- Each Top-10 threat links to the test or control that verifies its mitigation (7.9 scan, IAM
  simulate, E2E) — a threat model without verification decays into fiction.
