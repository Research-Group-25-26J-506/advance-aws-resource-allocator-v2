# Prompt: Test Strategy

## Goal
Produce `docs/testing/strategy.md`.

## Constraints
- Layers: unit, integration, contract, E2E, chaos, load, security.
- Unit coverage: 80% domain, 60% adapters. Integration: Testcontainers (MySQL + LocalStack).
- Contract: OpenAPI-driven schema tests; Pact for inter-service.
- E2E: Playwright in dev + staging.
- Chaos: worker survives RDS failover; DLQ handles poison messages; sync survives lock contention.
- Load: k6 hits N req/s, verifies p99 SLO.
- Security: dependency check, container scan, CodeQL, IaC scan, quarterly threat-model review.
- Every component in §3 has one concrete test enumerated.

## Acceptance
Every backend module has integration test entries. Every frontend page has an E2E entry.

## Enhancements (v2.1)
- Flake policy: quarantine label + auto-issue after 2 flakes/week; quarantined tests can't sit
  longer than a sprint — protects the "E2E blocks promotion" rule from eroding.
- Contract tests run against the **generated** client (same artifact the frontend uses), closing
  the spec→client gap.
- Add mutation testing (pitest) on the domain module as a coverage-quality check, not just a
  coverage-quantity one.
