# Prompt: Frontend RUM (OpenTelemetry JS)

## Goal
Instrument the frontend for Real User Monitoring with OpenTelemetry JS.

## Constraints
- WebTracerProvider with resource attributes service.name='platform-ui', service.version,
  deployment.environment.
- BatchSpanProcessor + OTLPTraceExporter to `/otlp/v1/traces` (proxied through the API).
- FetchInstrumentation with `propagateTraceHeaderCorsUrls` matching platform domains.
- Manual spans for: form.submit, wizard.step-change, catalog.filter-apply.
- Sampling: 20% at the SDK (network overhead).
- Attributes on every span: user.team, page.route. **Never PII or form values in attributes.**

## Acceptance
Filling and submitting the CreateResourceWizard produces a browser-side trace linked to the
backend trace in Tempo.

## Enhancements (v2.1)
- The API-side `/otlp` proxy authenticates the user, rate-limits per session, and caps payload
  size — an unauthenticated OTLP ingest path is a free log-injection/DoS vector.
- Error sampling override: spans with error status always sampled even under the 20% head rate.
- `page.route` uses the route **pattern** (`/requests/:id`), never the concrete URL — same
  cardinality discipline as backend metrics.
