# Prompt: Alert Rules

## Goal
Produce `observability/rules/alerts.yaml`.

## Constraints
- **platform-page:** DLQ depth > 0 for 5m; API 5xx rate > 5% for 10m; worker not processing while
  queue > 10 for 10m; SLO burn 14.4%/1h; RDS connections > 90% for 5m; sync stuck (inflight > 0
  for 15m).
- **platform-warn:** stack stuck *_IN_PROGRESS > 30m; event lag p99 > 30s for 15m; STS AssumeRole
  failure increase; drift detected; cost anomaly; approval latency > 8h.
- **platform-info:** no syncs in 7 days; template validation failures increase; slow user actions.
- Every alert: annotations summary, description, runbook_url
  (`https://platform.internal/runbooks/{alert_id}`), dashboard_url; labels severity, service, env;
  `$labels` interpolation in annotations.
- Deploy via `aws amp put-alert-manager-definition` + rule groups.

## Acceptance
Forcing each alert routes to the correct channel with a working runbook link.

## Enhancements (v2.1)
- Add meta-alerts on the pipeline itself: otel-gateway queue saturation / dropped spans, Loki
  ingest errors, AMP remote-write failures — alerting on the thing that carries your alerts.
- Every `for:` duration justified in a comment (why 10m not 5m) — future tuning needs the original
  reasoning.
- A quarterly "alert test" runbook + script that synthetically trips each page alert in STG.
