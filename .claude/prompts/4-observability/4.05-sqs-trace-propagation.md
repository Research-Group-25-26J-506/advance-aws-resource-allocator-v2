# Prompt: SQS Trace Propagation Utilities

## Goal
Build `SqsTracePropagator` with inject/extract methods preserving W3C trace context across the
queue boundary.

## Constraints
- `inject(context, sqsMessageAttributes)`: use
  `GlobalOpenTelemetry.getPropagators().getTextMapPropagator()` to write traceparent/tracestate
  into MessageAttributes as String types.
- `extract(sqsMessage)`: read MessageAttributes into a text map; return Context.
- Worker wraps processing in try-with-Scope of the extracted context. `sqs.receive` span from
  AWS SDK instrumentation; explicit child span `process-request` with the extracted parent.
- Tests validate a traceId inserted at publish is readable at consume.

## Acceptance
End-to-end trace HTTP POST → API span → SQS → Worker span visible as a single trace in Tempo.

## Enhancements (v2.1)
- SQS allows max 10 message attributes — propagator asserts headroom and fails loudly at publish
  time if the budget is blown.
- **Span-link fallback:** if extract yields no valid context (legacy/DLQ-redriven messages), start
  a new root with a span link instead of an orphan — keeps DLQ redrives debuggable.
