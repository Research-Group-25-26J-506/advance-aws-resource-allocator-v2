# Prompt: Spring Boot Instrumentation

## Goal
Wire every backend service for OpenTelemetry + Micrometer + JSON logging.

## Constraints
- Dependencies: micrometer-registry-otlp, opentelemetry-spring-boot-starter,
  logstash-logback-encoder, opentelemetry-api.
- application.yaml: `management.otlp.metrics.export.url=http://localhost:4318/v1/metrics`;
  `otel.exporter.otlp.endpoint=http://localhost:4318`; `otel.propagators=tracecontext,baggage`;
  sampler `parentbased_traceidratio` (1.0 at SDK; tail-sample at gateway).
- Resource attributes: service.name, service.version=${BUILD_SHA}, deployment.environment=${PLATFORM_ENV}.
- Histogram buckets SLO-aligned for http.server.requests (50ms…5s).
- MdcFilter injects trace_id, span_id, request_id, actor_id.
- logback-spring.xml: LogstashEncoder with includeMdcKeyName for all of the above.
- Custom Micrometer meters registered as beans (metrics catalogue, 4.4).

## Acceptance
One request produces logs with trace_id in Loki, metrics in AMP, and a trace in Tempo — all correlated.

## Enhancements (v2.1)
- `actor_id` in logs/MDC is the Cognito subject (opaque UUID), never email — keeps PII out of Loki.
- Uncaught-exception logs include the RFC 9457 `code` field so log-based alerting can group by error class.
- A tiny `/internal/telemetry-selftest` endpoint (dev-only) emits one log+metric+span for smoke
  verification in CI/E2E.
