# Prompt: Sidecar OTel Collector Config

## Goal
Produce `infrastructure/observability/otel-sidecar.yaml` — lightweight collector running as an
ECS sidecar on every application task.

## Constraints
- Receivers: otlp (grpc :4317, http :4318).
- Processors: memory_limiter (limit_mib 200, spike 50); batch (5s / 1000); resource
  (add deployment.environment, cloud.region, service.namespace).
- Exporters: otlphttp to gateway (`otel-gateway.platform.internal:4318`) with retry_on_failure +
  persistent sending_queue.
- Pipelines: traces, metrics, logs — same processor chain to gateway.
- Run as a sidecar in every api/worker/web-ui task definition.

## Acceptance
Sidecar starts, forwards traces to gateway. Metrics show up in AMP within 60 s.

## Enhancements (v2.1)
- `health_check` extension on :13133; the ECS container healthcheck hits it, and the app container
  gets `dependsOn: [{condition: HEALTHY}]` so instrumentation is up before traffic.
- Sidecar sized explicitly in the task def (0.25 vCPU / 256 MB) — memory_limiter must fit inside
  the container limit or ECS OOM-kills it before the limiter engages.
- Persistent sending_queue backed by `file_storage` extension on ephemeral storage; documented
  data-loss window on task replacement.
