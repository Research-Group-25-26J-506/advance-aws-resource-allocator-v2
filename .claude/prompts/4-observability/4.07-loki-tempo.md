# Prompt: Loki and Tempo Stacks

## Goal
Produce `infrastructure/observability/loki.yaml` and `tempo.yaml` — self-hosted on ECS Fargate.

## Constraints
- **Loki:** single-binary mode initially, S3 backend, retention 30d hot + lifecycle to Glacier
  after 90d. Config in versioned S3 / SSM Parameter Store. Internal NLB :3100.
- **Tempo:** single-binary mode initially, S3 backend, retention 14d. Internal NLB :4317 (OTLP)
  and :3200 (HTTP query).
- Both: auto-scale on CPU + memory; min 2, max 8. Task role: S3 CRUD on its own backend bucket only.
- CloudWatch dashboards per service (ingest rate, query latency, chunk count).
- Recording rules in SSM Parameter Store with change history.

## Acceptance
Log line pushed via gateway visible in Loki within 30 s. Trace queryable in Grafana within 60 s.

## Enhancements (v2.1)
- **Single-binary + min 2 tasks caveat resolved:** two independent single-binary Lokis behind an
  NLB give inconsistent query results. Either run 1 task (accept restart gaps; DEV) or jump to
  simple-scalable mode (read/write targets). State the choice per environment in an ADR — don't
  ship the ambiguous middle.
- Both services front their S3 with an index/query cache (embedded); WAL on ephemeral storage
  sized explicitly in the task def.
- Bucket policies deny non-TLS access and any principal except the service task role.
