# Prompt: Manifest JSON Schema

## Goal
Define the internal manifest schema that every template `manifest.json` must conform to.

## Constraints
- Required: templateId, version (semver), category, displayName, description, renderMode
  (parameter | jinja), parameterMap OR jinja marker.
- Optional: maturity (stable|beta|deprecated), owners, defaultsByEnv, executionRoleArn,
  estimatedMonthlyCost, cfnCapabilities, examples.
- Regex-validated: version `^\d+\.\d+\.\d+$`; templateId `^[a-z][a-z0-9-]{1,63}$`.
- `additionalProperties: false` at the root.
- `examples/` folder with 3 valid and 3 invalid manifests (test fixtures).

## Outputs
`backend/templatesync/src/main/resources/schemas/manifest-v1.json` (draft-07).

## Acceptance
Ajv validation of the S3 template manifest passes. A deliberately broken manifest (missing
templateId) fails with the correct error.

## Enhancements (v2.1)
- Schema itself carries `$id` and a `manifestSchemaVersion` field so a future manifest-v2 can be
  introduced without a flag-day (validator picks schema by declared version).
- `examples` entries are required to be valid against the template's own schema.json — validator
  stage 8 uses `examples[0]` for its dry-run, so this closes the loop.
- `defaultsByEnv` keys restricted to the enum {dev,stg,prod} via propertyNames.
