# Prompt: Template Validator Pipeline (8 stages)

## Goal
Build `TemplateValidator` running the full validation pipeline on a template version.

## Constraints
Stages in order; any failure marks the version failed. **All stages run** (no short-circuit) for a
complete report:
1. **Manifest schema** — manifest.json validates against the platform manifest schema (draft-07).
2. **User-facing schema syntax** — schema.json is a valid draft-07 JSON Schema.
3. **CFN syntax** — cfn-lint via shell; parse output.
4. **CFN security** — cfn-nag; HIGH-severity finding = fail; suppress comments IGNORED.
5. **Parameter map consistency** — every CFN parameter referenced in manifest.parameterMap exists
   in template.yaml; every required schema field maps to a CFN parameter.
6. **Tag policy** — Tags property includes all mandatory tag keys (variables allowed).
7. **Execution role** — manifest.executionRoleArn references a role deployed to target accounts (IAM query).
8. **CFN dry-run** — CreateChangeSet against a sandbox stack with example parameters; discard the ChangeSet.

- Each stage returns `{ passed, errors, warnings, duration_ms }`.
- Tracing: parent span `validate`, child span per stage.
- Metric: platform_template_validation_failures_total{stage, template}.

## Acceptance
A template passing all stages is uploaded; one failing stage 3 or 4 is rejected with the full
pipeline report.

## Enhancements (v2.1)
- Per-stage timeout (e.g. 60s; stage 8 gets 120s) so one hung subprocess can't wedge a sync;
  timeout = stage failure with a distinct error code.
- Stage 8 always deletes its ChangeSet in a finally block **and** a scheduled sweeper deletes
  orphaned `platform-validate-*` changesets — dry-run debris otherwise accumulates.
- cfn-lint/cfn-nag versions pinned in the worker image and reported in the pipeline output —
  validation results must be reproducible.
- Stage 2 additionally rejects schemas with external `$ref`s (pairs with wizard constraint in 2.4).
