# Prompt: Idempotency Layer

## Goal
Implement `IdempotencyFilter` in the Spring Boot api service.

## Constraints
- Applies to POST/PUT/PATCH/DELETE. Reads `Idempotency-Key`; UUIDv7 required (else 400).
- DynamoDB table `platform-idempotency`: PK key (string); attributes actor_id, endpoint,
  request_hash, response_status, response_body, response_headers, expires_at (TTL 24h).
- First request: conditional PutItem → run handler → store response → return it.
- Repeat with same key + same request_hash: return stored response with `X-Idempotent-Replay: true`.
- Same key + DIFFERENT request_hash: 422 "idempotency key already used with different payload".
- In-flight (row exists, response not stored): 409 with Retry-After.
- Filter transparent to handlers.

## Acceptance
Double-clicking submit never creates two requests. Changing the payload with the same key → 422.

## Enhancements (v2.1)
- Key scope includes `actor_id` + endpoint in the partition key hash — two users independently
  generating the same UUID must not collide into each other's responses.
- DynamoDB item limit handled: responses > 350 KB spill body to S3 with a pointer in the item.
- Crash-between-reserve-and-store recovery: in-flight rows carry a `reserved_at`; rows older than
  a bound (e.g. 2× max handler time) are treated as failed and retried rather than 409-ing forever.
