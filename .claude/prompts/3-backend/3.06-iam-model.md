# Prompt: Platform IAM Model

## Goal
Produce CloudFormation for the platform's IAM roles (separate stack; per-template roles in a
nested stack).

## Constraints
- **platform-api-task-role:** SQS SendMessage (requests queue); S3 GetObject (templates);
  DynamoDB CRUD (idempotency + locks); Secrets Manager Get on `platform-secrets/*`; CloudWatch
  logs; X-Ray. **No CFN or STS-to-target.**
- **platform-worker-task-role:** SQS Receive/Delete (requests queue); S3 GetObject (templates);
  STS AssumeRole **only** on per-template execution roles (or spoke roles in Phase 4); logs;
  X-Ray. **No direct resource permissions.**
- **platform-event-listener-role** (Lambda): rds-db:connect (or Secrets Manager); logs.
- **platform-drift-detector-role** (Lambda): cloudformation:DetectStackDrift,
  DescribeStackDriftDetectionStatus, DescribeStackResourceDrifts; STS AssumeRole to spoke roles.
- **platform-otel-gateway-task-role:** aps:RemoteWrite to AMP; write to Loki/Tempo S3 backends.
- **platform-observability-task-role** (loki/tempo/grafana): read/write to their own S3 backend only.
- **Per-template execution roles:** one per template (exec-role-s3-bucket, exec-role-rds-mysql,
  exec-role-ecs-service). Trust: only platform-worker-task-role with `sts:ExternalId`.
  Permissions: minimum viable for that template.
- Phase 4 spoke roles: deployed via StackSets from the management account.

## Outputs
`infrastructure/platform/iam.yaml` (platform-side roles) + `infrastructure/platform/roles/`
(per-template role templates).

## Acceptance
cfn-nag clean. IAM Access Analyzer reports no unintended external principals.
`iam:simulate-custom-policy` confirms scoped permissions.

## Enhancements (v2.1)
- A **permissions boundary** (`platform-execution-boundary`) attached to every per-template
  execution role, explicitly denying `iam:*` (except tightly scoped PassRole), `organizations:*`,
  `account:*`, and billing actions — caps blast radius even if a template's policy is too broad.
- Role names prefixed `platform-` and parameterised by `EnvironmentName` so multiple environments
  can coexist in one sandbox account.
- Explicit deny on `s3:PutObject` to the templates bucket for everything except the sync path —
  encodes the "S3 is a downstream cache" rule in IAM.
