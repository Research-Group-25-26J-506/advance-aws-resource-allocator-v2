# Prompt: Template Renderer

## Goal
Implement `TemplateRenderer`: maps user-facing form data to CloudFormation parameters and computes
mandatory tags.

## Constraints
- User-facing JSON Schema is **not** 1:1 with CFN parameters. Mapping declared in the template
  `manifest.json` (`parameterMap`: schema path → CFN param name).
- Array of complex objects (e.g. S3 lifecycle rules) → Jinja-style CFN body templating. Support
  both `parameter` and `jinja` modes per manifest.
- Mandatory tag computation centralised: takes request + team; returns Tags list.
  Owner=requester email; CostCenter=team.cost_center; Environment=request.environment;
  Application=template.application or requester input; ManagedBy='Platform';
  PlatformRequestId=request.id; SourceCommitSha=template_version.commit_sha.
- Render output logged (secrets redacted) for audit reconstruction.
- Golden-file tests for S3, RDS, ECS service — expected CFN body + parameters checked into the repo.

## Acceptance
Golden-file tests pass for at least three templates. Adding a fourth is a simple pattern extension.

## Enhancements (v2.1)
- Jinja engine runs **sandboxed**: autoescape on, no filesystem/module access, allow-listed
  filters only, render timeout — template authors are semi-trusted, the renderer must not be an
  RCE surface.
- Rendered CFN body size checked against the 51,200-byte inline limit; larger bodies auto-upload
  to the cfn-uploads bucket and use TemplateURL.
- Unmapped schema fields are a **hard error** at render time (mirrors validator stage 5) — silent
  drops of user input are the worst failure mode here.
