# Prompt: GitHub App Integration

## Goal
Build a GitHub App integration used by two features: ECS deployment (source pull + status checks)
and template sync (repo access).

## Constraints
- One GitHub App per environment (dev/stg/prod) for target isolation.
- Permissions: repository contents (read), metadata (read), checks (write), deployments (write).
  Subscribe to push, pull_request, deployment.
- Private key in Secrets Manager; rotate quarterly via runbook.
- Webhook receiver `POST /api/v1/webhooks/github`: verify `X-Hub-Signature-256` against the
  webhook secret; idempotent on `X-GitHub-Delivery`.
- Installation token minted per operation, expires in 1 hour, never logged.
- Client methods: listInstallations(), listRepos(installationId), getBranchHead(repo, branch),
  fetchTarball(repo, sha) returning a stream, createCheckRun(repo, sha, status),
  createDeployment(repo, env).
- Tarball fetch: extract to `/tmp/{op_id}/` sandbox, size cap 50 MiB, file cap 5000, reject
  symlinks and paths containing `..`.
- Metrics: github_api_calls_total{op, result}, github_api_duration_seconds, github_token_mint_total.

## Acceptance
A sample repo can be cloned via the App; webhooks verify correctly; installation tokens never
appear in logs.

## Enhancements (v2.1)
- App JWT minting spelled out: RS256, `iat` skewed −60s, `exp` ≤ 10 min — the classic clock-skew
  401 documented away.
- Rate-limit handling: honour `Retry-After` / `x-ratelimit-remaining`; surface a
  `github_rate_limited_total` metric.
- Signature verification is constant-time compare; webhook handler returns 401 (not 400) on bad
  signature and never echoes payload contents.
- Conditional requests (ETag) for branch/repo listings to conserve rate limit.
