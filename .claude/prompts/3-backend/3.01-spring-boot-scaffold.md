# Prompt: Spring Boot Multi-Module Scaffold

## Goal
Scaffold the Spring Boot backend as a multi-module Gradle 8 project supporting two services
(`api`, `worker`).

## Constraints
- Hexagonal architecture: the `domain` module has **zero infrastructure imports**.
- Java 21, Spring Boot 3.3+, Gradle 8. All modules use logback-json + Micrometer.
- OpenAPI spec generated at `/openapi.json` for the api service.
- Long-running operations return **202 with request_id**; nothing blocks HTTP threads.
- All endpoints authenticated; `@PreAuthorize` with SpEL for RBAC.
- Global `@ControllerAdvice` returns RFC 9457 Problem JSON.
- OpenTelemetry auto-configuration active from day one (see §4.3).
- Every service has an integration test using Testcontainers (MySQL + LocalStack).
- Both services build to Docker images: `eclipse-temurin:21-jre` + jar copy.
- Health probes: `/actuator/health/liveness` and `/actuator/health/readiness`.

## Outputs
`backend/` multi-module Gradle project. Modules: `api`, `worker`, `domain`, `persistence`,
`aws-clients`, `messaging`, `security`, `observability`, `templatesync`, `app-common`.

## Acceptance
`./gradlew build` succeeds. Each service starts, exposes `/actuator/health`, and passes
Testcontainers integration tests.

## Enhancements (v2.1)
- Gradle **version catalog** (`libs.versions.toml`) pins every dependency; Spotless + ErrorProne
  wired into `check`.
- ArchUnit test enforcing the hexagonal rule ("domain depends on nothing infrastructural") — the
  architecture constraint becomes a failing test, not a convention.
- Docker images built with layered jars (`bootBuildImage` or layertools) for cacheable layers.
- Graceful shutdown enabled (`server.shutdown=graceful`, 30s) — required for clean ECS rolling deploys.
