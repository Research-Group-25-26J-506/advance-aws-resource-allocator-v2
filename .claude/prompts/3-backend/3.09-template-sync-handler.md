# Prompt: Template Sync Handler

## Context
Sync is a request type. The worker branches on `type=TEMPLATE_SYNC` and invokes this handler.

## Goal
Implement `TemplateSyncHandler` in `backend/templatesync`.

## Constraints
1. Acquire distributed lock `template-sync` via DynamoDB conditional write (3.10). Fail with
   SYNC_FAILED on lock timeout.
2. Resolve commit SHA: `req.commit_sha` OR `github.getBranchHead(REPO, req.branch)`.
3. Fetch tarball via GitHub App (3.11).
4. Walk `templates/{id}/v{x.y.z}/` tree; build TemplateFound entries.
5. Compare against RDS state → `{ added, unchanged, changed (immutability violation), removed }`.
6. **Fail-fast if `changed` non-empty.** Fail if `removed` non-empty and `!req.allow_removed`.
7. Validate every `added` via the full pipeline (3.12).
8. If `mode=DRY_RUN`, stop after validation and report.
9. Any validation failure fails the sync entirely (**atomic — zero partial uploads**).
10. For each added: upload to `s3://platform-templates/{templateId}/{version}/`, insert
    template + template_versions rows (transaction).
11. Release lock. Complete with summary. Audit log entry.
- Tracing: root span `template-sync` with attributes git.sha, actor.id, mode; child spans per stage.
- Metrics: platform_template_sync_total{result}, platform_template_sync_duration_seconds,
  platform_templates_synced_total{action}, platform_template_validation_failures_total{stage}.

## Acceptance
Same commit_sha synced twice returns the original sync record (idempotency). Any validation
failure results in ZERO S3 uploads. A concurrent sync attempt fails with a clear lock message.

## Enhancements (v2.1)
- Ordering fixed explicitly: **upload S3 first, then commit the DB transaction**; a crash between
  the two leaves unreferenced S3 objects (harmless, GC-able) rather than DB rows pointing at
  missing objects. Startup GC job removes unreferenced object prefixes older than 24h.
- Each pipeline step appends a persisted `sync_events` row (this is what powers SSE resume in 2.10).
- Lock heartbeat runs for the duration; a sync exceeding lock TTL without heartbeat is a bug —
  alarmed via `lock_heartbeat_failures_total`.
- `SyncNonce`-style force-resync input documented for ops (bypass "same SHA" idempotency short-circuit).
