# Prompt: Worker Service (Orchestrator)

## Goal
Build `backend/worker` as a Spring Boot service consuming SQS.

## Constraints
- Long-polling consumer (WaitTimeSeconds=20). Concurrent processors configurable, default 10.
- Handler branches on `message.type`: PROVISION, DEPLOY, DELETE, TEMPLATE_SYNC, DRIFT_CHECK.
- **Provision handler:**
  1. Load Request from RDS. Skip if status != QUEUED (idempotency).
  2. Load TemplateVersion, fetch CFN body from S3.
  3. Render params via TemplateRenderer (3.8).
  4. Compute mandatory tags via TagPolicyService.
  5. STS AssumeRole (per-template execution role; cross-account in Phase 4).
  6. CFN CreateStack with `ClientRequestToken=idempotency_key`, `Capabilities=[CAPABILITY_NAMED_IAM]`.
  7. Persist StackId; transition to CREATE_IN_PROGRESS.
- Sync handler: see 3.9 (fetch tarball, walk, validate, upload).
- Failure handling: validation failure → FAILED_VALIDATION; retryable AWS error → leave message on
  queue; non-retryable → CREATE_FAILED. Poison → DLQ after 5 redeliveries.
- MDC fields request_id, template_id, environment, region on every log line.
- Metrics: worker_inflight (gauge), messages_consumed, stack_create_initiated,
  stack_create_failed, sts_assume_failed, processing_duration_seconds.
- Trace propagation: extract W3C traceparent from SQS message attributes (4.5).

## Acceptance
1000 synthetic messages process with zero data loss. Failures land in the correct status.
Traces continue from API through worker.

## Enhancements (v2.1)
- Visibility-timeout heartbeat: long-running handlers extend `ChangeMessageVisibility`
  periodically so slow syncs don't get redelivered mid-flight.
- Graceful shutdown drains in-flight handlers (stop polling → await completion, 60s cap) before
  the ECS task stops — pairs with rolling deploys.
- MDC is cleared in a finally block per message — thread pools leak context otherwise.
- Retryable-vs-terminal AWS error classification centralised (throttling/5xx = retryable;
  validation/AccessDenied = terminal) and unit-tested.
