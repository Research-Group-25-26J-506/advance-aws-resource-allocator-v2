# Prompt: CloudFormation Event Listener Lambda

## Goal
Build `lambdas/cfn-event-listener` in Python 3.12: subscribes to CloudFormation stack events and
updates RDS.

## Constraints
- EventBridge rule: source `aws.cloudformation`, detail-type "CloudFormation Stack Status Change".
- Lambda in VPC (private app subnets), uses RDS Proxy.
- Handler: parse event → StackId, stack-name, status, status-reason, resource-type, timestamp, account.
- Only act on top-level stack events (resource-type == `AWS::CloudFormation::Stack`).
- Look up request by `cfn_stack_id` (indexed). If not found, log and exit — stack not owned by platform.
- Compute next status; **conditional UPDATE** (`WHERE current_status != new_status`) to handle
  out-of-order events.
- On terminal success, pull stack Outputs and insert into resource_outputs.
- ADOT layer for OpenTelemetry (Python auto-instrumentation).
- Idempotent: replaying any event must not double-write.

## Acceptance
Full lifecycle — including ROLLBACK_FAILED followed by manual ContinueUpdateRollback — reflected
accurately.

## Enhancements (v2.1)
- Lambda gets an **on-failure destination / DLQ** (SQS) + alarm — a dropped event silently strands
  a request in *_IN_PROGRESS otherwise.
- Ordering guard: persist `event_timestamp`; ignore events older than the last applied one for the
  same stack (EventBridge is at-least-once, unordered).
- DB credentials fetched via Secrets Manager with in-container caching (extension or lru cache);
  connections short-lived through RDS Proxy to avoid pinning.
- Reconciliation companion documented: scheduled DescribeStacks sweep for requests stuck
  *_IN_PROGRESS > 30 min (backstop for missed events; pairs with the stack-stuck alert in 4.12).
