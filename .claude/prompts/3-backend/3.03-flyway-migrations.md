# Prompt: Flyway Migrations (Aurora MySQL 8)

## Goal
Produce Flyway migration files under `backend/persistence/src/main/resources/db/migration`.

## Constraints
- `V001__init.sql`: users, teams, user_roles, templates, template_versions, requests,
  request_events, resource_outputs.
- `V002__approvals.sql`: approvals. `V003__audit.sql`: audit_log. `V004__tag_policies.sql`: tag_policies.
- `V005__sync.sql`: template_syncs (id UUIDv7, actor_id, commit_sha varchar(40), branch
  varchar(255), mode enum('APPLY','DRY_RUN'), status varchar(40), started_at, completed_at,
  summary_json JSON, error_json JSON); sync_events (append-only, like request_events);
  distributed_locks (name PK, holder varchar(255), acquired_at, expires_at).
- `V006__runbooks.sql`: runbooks (id, path_in_repo, title, severity, alerts_covered JSON, updated_at).
- PK: `BINARY(16)` UUIDv7 for time-ordered indexing; BIGINT auto-increment only for append-only
  high-volume tables (request_events, sync_events, audit_log).
- All timestamps `TIMESTAMP(6)` UTC. FK constraints enabled; ON DELETE RESTRICT except audit_log (no FKs).
- Indexes: (requester_id, status), (environment, status), (submitted_at) on requests;
  (request_id, occurred_at) on event tables.
- `V999__seed_dev.sql`: sample data, applied only via profile.

## Acceptance
Migrations run cleanly from an empty DB. EXPLAIN plans on recent-requests and approvals-inbox
queries use indexes. Seed profile populates enough data for E2E tests.

## Enhancements (v2.1)
- Explicit `CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci` on database and tables — never
  inherit server defaults.
- `incidents` table added (rollback workflow 7.12 writes here) so it isn't invented ad hoc later.
- Migration checksum policy documented: never edit an applied migration; forward-fix only
  (aligns with 7.6).
- Every JSON column gets a CHECK (`JSON_VALID`) constraint.
