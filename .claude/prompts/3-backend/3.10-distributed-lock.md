# Prompt: Distributed Lock Service (DynamoDB)

## Goal
Implement `DistributedLockService` with acquire/release/heartbeat backed by DynamoDB.

## Constraints
- Table `platform-locks`, PK `name` (string). Attributes: holder, acquired_at, expires_at, heartbeat_at.
- `acquire(name, ttl)`: PutItem with ConditionExpression
  `attribute_not_exists(name) OR expires_at < :now`. Returns Lock or throws LockTimeout.
- Lock implements AutoCloseable; try-with-resources releases on close.
- Heartbeat: background thread updates expires_at every ttl/3, extending ownership.
- `release()`: DeleteItem with ConditionExpression `holder = :holder`.
- Metrics: lock_acquire_total{name,result}, lock_hold_duration_seconds, lock_heartbeat_failures_total.
- Trace attribute `lock.name` on the span holding the lock. Test with LocalStack.

## Acceptance
Two workers race — exactly one succeeds. Worker crash frees the lock after TTL. Heartbeat prevents
expiry while held.

## Enhancements (v2.1)
- `holder` = `{taskArn}-{uuid}` so a restarted task can't accidentally release a lock a previous
  incarnation held.
- Document the **fencing caveat**: TTL locks don't prevent a paused-then-resumed holder from
  acting after expiry. Mitigation here: sync work re-validates status in DB before each write
  (fencing by state check), noted in 3.9.
- Clock source is DynamoDB-side comparison against caller-provided `:now` from a monotonic-safe
  source; document the assumption of loosely synced clocks (NTP on Fargate is fine).
