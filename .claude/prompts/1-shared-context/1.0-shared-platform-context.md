# Shared Platform Context (v2.1)

Paste this once at the top of any AI conversation. Every prompt in this pack builds on it.

You are helping build an internal **AWS Self-Service Deployment Platform**. Developers use it to
provision approved AWS resources and deploy ECS workloads through a web UI without writing
CloudFormation themselves.

## Stack
- **Frontend:** React 18 + TypeScript + Vite + AWS Cloudscape Design System. Served via CloudFront + ALB.
- **Backend:** Spring Boot 3, Java 21, Gradle. Two services (`api`, `worker`) on ECS Fargate.
- **Lambdas:** Python 3.12 with ADOT layer for OpenTelemetry.
- **Data:** Aurora MySQL 8 (Multi-AZ), SQS + DLQ, DynamoDB (idempotency + distributed lock), S3 (template registry, versioned).
- **Eventing:** EventBridge for CloudFormation stack events → Lambda updater → Aurora.
- **Auth:** Cognito user pool + OIDC.
- **Resource execution:** CloudFormation, per-template execution IAM roles, cross-account via STS AssumeRole with ExternalId.
- **ECS deploy subsystem:** GitHub App → CodeBuild → ECR → CloudFormation.

## Observability (open-source)
- **Instrumentation:** OpenTelemetry SDKs across all services and frontend.
- **Collection:** OTel Collector as sidecar per ECS task + central gateway service.
- **Metrics:** AWS Managed Prometheus (AMP). **Logs:** Grafana Loki on ECS Fargate, S3 backend.
  **Traces:** Grafana Tempo on ECS Fargate, S3 backend. **Visualisation:** Grafana (self-hosted or AMG).
- **Alerts:** Alertmanager routing to PagerDuty + Slack.
- **App logs:** Fluent Bit sidecar forwarding to OTel gateway (bypassing CloudWatch for app logs).

## Template sync
Templates live in a separate GitHub repo (`platform-templates`) as versioned folders. Platform
admins trigger sync from the admin console: pull repo → validate every template → publish new
versions to S3. **Versions are immutable once published.**

## Domain concepts
- **Template** = CloudFormation template + JSON Schema + manifest. Versioned; immutable when PUBLISHED.
- **Request** = one user submission bound to one template version. Rich lifecycle
  (PENDING_VALIDATION, PENDING_APPROVAL, QUEUED, CREATE_IN_PROGRESS, CREATE_COMPLETE, ROLLBACK_*, …).
- **Environment** = DEV, STG, PROD. Separate AWS accounts. PROD requires approval.
- **Mandatory tags:** Owner, CostCenter, Environment, Application, ManagedBy=Platform, PlatformRequestId.

## Deployment
GitHub Actions runs CI (PR validation) and CD (deploy platform to AWS). Federated auth via OIDC —
no long-lived AWS keys in GitHub. Three GitHub Actions environments: `platform-dev` (auto on main),
`platform-stg` (auto after dev green), `platform-prod` (manual approval).

## Source-of-truth rules
- **CloudFormation** = what exists in AWS.
- **Aurora** = what was asked for.
- **Git (platform-templates repo)** = template source of truth.
- **S3** = downstream cache.

## Portability rules (new in v2.1 — apply to EVERY artefact you generate)
- Never hardcode account IDs, regions, or bucket names. Bucket names always include
  `${AWS::AccountId}` and an environment suffix.
- Every stack takes an `EnvironmentName` parameter (dev|stg|prod).
- Cross-stack wiring goes through **SSM Parameter Store** under `/platform/{env}/...`
  (e.g. `/platform/dev/templates-bucket`), never CloudFormation Exports.
- Any artefact must deploy cleanly into a **brand-new AWS account** given only the quickstart
  stack (Section 10) as a precondition.
