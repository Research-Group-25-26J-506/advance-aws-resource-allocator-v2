# Prompt: Sync Preview Modal

## Context
Clicking "Preview changes" on the templates-admin banner shows a diff modal.

## Goal
Produce `SyncPreviewModal.tsx` as a Cloudscape `Modal`.

## Inputs
- `GET /api/v1/admin/templates/sync/preview?commit_sha=...` →
  `{ added: [{template_id, version, changelog}], unchanged: [...], changed: [...], removed: [...], failed_validation: [...] }`.

## Constraints
- Modal header: `Preview: {N} new, {N} unchanged, {N} violations`.
- Body: Cloudscape `Table` — Template, Version, Status (Badge: new / unchanged /
  IMMUTABILITY_VIOLATION / REMOVED / FAILED_VALIDATION), Notes.
- "changed" rows (immutability violations): red Badge + reason.
- "failed_validation" rows: expandable to show which stage failed (cfn-lint/cfn-nag/schema/dry-run).
- Footer: "Cancel" (link) and "Apply sync" (primary; disabled if any violations or validation failures).
- Loading state while preview computes (10–30 s).
- "Apply sync" triggers `POST /api/v1/admin/templates/sync` (not preview), closes modal,
  navigates to `/admin/sync/:id`.

## Acceptance
Preview mode runs the full validator pipeline without uploading. Applying the sync uses the
**same commit_sha** as the preview.

## Enhancements (v2.1)
- The apply POST carries `{ commit_sha }` from the preview response, never re-resolves HEAD —
  eliminates the TOCTOU gap between preview and apply.
- Preview requests are cancellable (AbortController) if the admin closes the modal mid-compute.
- Server caches preview results by commit_sha for 10 min (see 5.3); the modal shows
  "computed 2 min ago" with a refresh link.
