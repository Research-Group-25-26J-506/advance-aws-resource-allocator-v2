# Prompt: Sync Detail and History

## Context
Track a specific sync operation and browse historical syncs.

## Goal
Produce `SyncHistoryPage.tsx` and `SyncDetailPage.tsx`.

## Inputs
- `GET /api/v1/admin/templates/sync` → list of syncs.
- `GET /api/v1/admin/templates/sync/:id` → single sync detail.
- `GET /api/v1/admin/templates/sync/:id/events` (SSE).

## Constraints
- `SyncHistoryPage` table: Started, Actor, Commit SHA (short), Status (`StatusIndicator`),
  Duration, Templates-changed count.
- `SyncDetailPage`: header + tabs Overview / Details / Logs / Trace.
  - Overview: `KeyValuePairs` of commit_sha, branch, mode, actor, started, completed, duration;
    result summary table (added/unchanged/…).
  - Details: expandable per-template card showing every validation stage result.
  - Logs: Grafana Loki iframe filtered to `sync_id`. Trace: Grafana Tempo iframe for the sync trace.
- In-progress sync: top progress bar + SSE-driven step indicator
  ("Validating rds-mysql v1.2.0 (4 of 6)").
- Failed syncs: dismissible `Alert` with structured failure report.

## Acceptance
A completed sync shows every processed template with per-stage results. In-progress sync updates
in real time via SSE.

## Enhancements (v2.1)
- Commit SHA links out to the GitHub commit; actor links to the audit log filtered to that actor.
- SSE reconnect resumes from `Last-Event-ID` so a dropped connection doesn't lose step events
  (server persists sync_events — see 3.9).
- History table supports filtering by status and mode (APPLY vs DRY_RUN).
