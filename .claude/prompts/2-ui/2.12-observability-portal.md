# Prompt: Observability Portal

## Context
Single page that links out to Grafana dashboards and embeds key panels.

## Goal
Produce `ObservabilityPage.tsx` — an in-app portal to the observability platform.

## Inputs
- `GRAFANA_BASE_URL` env var.
- `GET /api/v1/observability/health` → `{ grafana, loki, tempo, prometheus, alertmanager }` status.

## Constraints
- Top: `Container` with `StatusIndicator` per observability backend.
- Grid of Cards linking to canonical dashboards (Platform health, Request lifecycle, Per-template
  performance, Per-team usage, Approvals workload, SLO tracker, Security & audit, Template sync).
- Each card: name, description, "Open in Grafana" button, small embedded preview iframe (60px tall).
- Panel embedding uses Grafana `/d-solo` with **signed URLs from the backend**
  (never expose API keys client-side).
- "Alert history" at bottom: table from `GET /api/v1/observability/alerts?since=24h`.
- Environment filter (DEV/STG/PROD) at page top.

## Acceptance
All eight dashboards accessible from one page. Alert history updates every 60s. Backend status shown clearly.

## Enhancements (v2.1)
- Preview iframes lazy-load on viewport entry (IntersectionObserver) — eight live iframes on mount
  is a Grafana query-load footgun.
- Document the CSP requirement: Grafana must send `frame-ancestors` allowing the platform origin;
  add this to the Grafana config prompt (4.8).
- Alert rows link to their runbook (`runbook_url` annotation) and to the alert's dashboard.
