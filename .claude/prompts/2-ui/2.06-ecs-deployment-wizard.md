# Prompt: ECS Deployment Wizard

## Context
Specialised flow to deploy a containerised service from GitHub through the platform.

## Goal
Produce `DeployServicePage.tsx` as a 7-step `Wizard`.

## Inputs
- `GET /api/v1/integrations/github/installations` → repos visible to the GitHub App.
- `GET /api/v1/integrations/github/repos/:owner/:repo/branches` → branches.
- `GET /api/v1/regions?env=selected` → allowed regions.
- `POST /api/v1/deployments` (returns `deployment_id`).

## Constraints
- **Step 1 "Source":** repo `Autosuggest`, branch `Select`, Dockerfile path (default `./Dockerfile`),
  build args (`AttributeEditor`).
- **Step 2 "Service":** service name, environment, region, type (Radio: Long-running / Scheduled /
  One-shot). If long-running: ALB integration toggle + host header + path prefix + health check path.
- **Step 3 "Compute":** task CPU (256/512/1024/2048/4096), memory (dependent on CPU), desired
  count, platform version, networking mode locked to `awsvpc`.
- **Step 4 "Auto-scaling":** toggle; if on, target-tracking on CPU/Memory with target, min, max, cooldowns.
- **Step 5 "Env & Secrets":** two tables — plain env vars, and secrets (validate ARN format).
- **Step 6 "Tags":** same mandatory + optional pattern as 2.4.
- **Step 7 "Review":** summary, cost estimate, CFN params JSON, confirmation checkbox.
- PROD `Alert` banner on every step: "PROD deployments require approval before build starts."
- `sessionStorage` persistence between steps. On submit → `/deployments/:id`
  (RequestDetailPage variant with a Build tab).

## Acceptance
Wizard navigation works forward and back. Refresh preserves entered data. Submission failure keeps state.

## Enhancements (v2.1)
- Fargate CPU→memory valid-combination map encoded as a constant (e.g. 256→512/1024/2048MB …);
  memory `Select` options derive from selected CPU — invalid combos unrepresentable.
- Secret ARN validation regex covers both Secrets Manager and SSM Parameter ARNs; inline docs link.
- Service name validated against ECS naming rules + uniqueness check
  (`GET /api/v1/deployments?name=` debounce) before Step 2 exit.
- Branch list refreshes when repo changes; stale selections cleared.
