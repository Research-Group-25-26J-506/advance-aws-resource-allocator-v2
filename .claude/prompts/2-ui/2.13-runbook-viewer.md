# Prompt: Runbook Viewer

## Context
On-call engineers open runbooks from alerts. Runbooks live in the platform-code repo as markdown;
the UI renders them.

## Goal
Produce `RunbooksPage.tsx` and `RunbookViewerPage.tsx`.

## Inputs
- `GET /api/v1/runbooks` → `{ id, title, alerts_covered, severity, last_updated }[]`.
- `GET /api/v1/runbooks/:id` → markdown content + metadata.

## Constraints
- `RunbooksPage`: filterable table — Title, Severity Badge, Alerts covered, Last updated, Owner.
- `RunbookViewerPage`: renders markdown with syntax highlighting. Sticky sidebar with sections
  (What it means, Detection, Triage, Immediate actions, Recovery, RCA).
- Every command block gets a copy button.
- "Report this runbook is outdated" link → creates a GitHub issue via API.
- Deep-link support: `/runbooks/:id?section=triage` jumps to section.

## Acceptance
A new on-call engineer can open a runbook, copy the diagnostic commands, and follow the steps
without leaving the page.

## Enhancements (v2.1)
- Markdown rendered through a sanitizing pipeline (e.g. remark + rehype-sanitize) — runbooks are
  repo content, but stored-XSS via markdown is a classic hole; no raw HTML passthrough.
- "Last reviewed" surfaced with a warning Badge when older than 90 days (pairs with 3.14 CI check).
- Offline resilience: last-viewed runbooks cached in memory so a flapping API doesn't strand on-call.
