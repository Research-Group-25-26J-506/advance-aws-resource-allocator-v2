# Prompt: Approvals Inbox

## Context
Where approvers review PROD requests and approve or reject.

## Goal
Produce `ApprovalsPage.tsx` — a focused inbox.

## Inputs
- `GET /api/v1/approvals?status=pending`
- `GET /api/v1/approvals/:id/diff` → diff vs last successful version (for updates).
- `POST /api/v1/approvals/:id/approve`, `/reject` (comment required for reject).

## Constraints
- Top: counter Badges "Pending: N", "Approved today: N", "Rejected today: N".
- Main: Cloudscape `Table` with multi-select. Columns: Requester, Resource, Environment, Region,
  Submitted, Risk (computed low/medium/high from cost & sensitivity), Estimated monthly cost.
- Row click → side `Drawer`: full summary, `KeyValuePairs` parameters, diff-vs-last, comment
  `Textarea`, Approve (primary), Reject (link).
- Bulk actions: Approve selected (only if all low-risk); Reject selected.
- Approver cannot approve their own request (button disabled with tooltip).

## Acceptance
Approver moves through 10 requests in under 90 seconds without leaving the page.

## Enhancements (v2.1)
- Optimistic concurrency: approve/reject send `If-Match` with the approval row ETag; a 412 (someone
  else already actioned it) refreshes the row with a clear Flashbar message.
- Keyboard flow: `j/k` row navigation, `a`/`r` open the action drawer — supports the 90-second target.
- Self-approval is enforced server-side too (UI disablement is UX, not security).
- Every decision writes an audit entry with the comment; UI surfaces "decided by X at T" post-action.
