# Prompt: Bootstrap Stack

> New in v2.1: the quickstart stack (Section 10) is the portable superset of this bootstrap —
> prefer it for fresh accounts. This prompt remains the reference for the full platform account.

## Context
Applied once, manually, before anything else exists. All subsequent stacks deploy via CI.

## Goal
Produce `infrastructure/bootstrap/bootstrap.yaml`.

## Constraints
- All bucket names include `AWS::AccountId` (global-name collisions).
- Lifecycle rules: templates keep all versions; build-metadata expire after 90d; observability →
  Glacier after 90d.
- OIDC trust conditions: `token.actions.githubusercontent.com:sub` matches
  `repo:{org}/platform:ref:refs/heads/main` for deploy role; `repo:{org}/platform:pull_request`
  for plan role.
- cfn-lint + cfn-nag clean. One-time apply script `infrastructure/bootstrap/apply.sh`.

## Outputs
- S3: platform-templates (versioned, SSE, BPA on), platform-cfn-uploads, platform-build-metadata,
  platform-observability-loki-{env}, platform-observability-tempo-{env}.
- ECR platform-images (scan on push, keep last 20 tagged).
- IAM OIDC provider for token.actions.githubusercontent.com.
- IAM roles platform-ci-deploy-role, platform-ci-plan-role.

## Acceptance
`aws cloudformation deploy` succeeds. GitHub Actions can assume the deploy role via OIDC.

## Enhancements (v2.1)
- Every bucket gets a policy denying `aws:SecureTransport=false` and (templates bucket) denying
  PutObject except from the sync path — cfn-nag will ask anyway.
- Bootstrap **publishes its outputs to SSM** under `/platform/{env}/...` (templates-bucket,
  ecr-repo, deploy-role-arn) — this is what makes every downstream stack account-agnostic.
- `apply.sh` is idempotent (`deploy`, not `create-stack`) and prints the SSM parameters it wrote.
