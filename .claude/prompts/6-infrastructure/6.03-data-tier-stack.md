# Prompt: Data Tier Stack

## Goal
Produce `infrastructure/platform/data.yaml` — Aurora, SQS, DynamoDB, S3.

## Constraints
- Aurora MySQL 8.0: provisioned, Multi-AZ, t4g.medium primary + reader, 30d backups.
  Master password in Secrets Manager (rotation 90d). RDS Proxy attached.
  Enhanced monitoring 30s + Performance Insights.
- SQS: platform-requests (standard, 5min visibility, 14d retention); platform-requests-dlq;
  redrive maxReceiveCount 5.
- DynamoDB: platform-idempotency (PK key; TTL expires_at); platform-locks (PK name; TTL expires_at).
- S3 buckets are bootstrap's; this stack only adds the sync metadata bucket if needed.
- Outputs consumed by the compute stack (via SSM).

## Acceptance
Aurora reachable from ECS tasks via RDS Proxy. Rotation configured but not yet run.

## Enhancements (v2.1)
- `DbTier` parameter: dev = Aurora Serverless v2 (min 0.5 ACU) single instance; prod = the
  provisioned Multi-AZ pair. A Multi-AZ t4g.medium pair alone is ~$120/month — untenable in a
  student sandbox and unnecessary in DEV.
- Aurora `DeletionProtection: true` + final snapshot on prod; storage encryption on everywhere.
- DynamoDB tables PAY_PER_REQUEST with point-in-time recovery on idempotency (it stores response
  bodies).
- SQS visibility timeout justified against worker max processing time in a comment (and the
  heartbeat from 3.4 noted).
