# Prompt: Networking Stack

## Goal
Produce `infrastructure/platform/network.yaml` — the platform VPC.

## Constraints
- VPC 10.0.0.0/16, 3 AZs. Public + private-app + private-data subnets per AZ.
- IGW; one NAT Gateway per AZ. Routes: public → IGW; private-app → NAT; private-data → no NAT.
- Interface endpoints: cloudformation, sts, secretsmanager, ssm, ssmmessages, ec2messages,
  ecr.api, ecr.dkr, logs, monitoring, sqs, elasticloadbalancing. Gateway endpoints: s3, dynamodb.
- Security groups: sg-alb (443 from 0/0), sg-ecs (from sg-alb; from itself), sg-rds (3306 from
  sg-ecs), sg-vpce (443 from sg-ecs), sg-loki (3100 from sg-ecs), sg-tempo (4317/3200 from sg-ecs).
- NACLs default. VPC Flow Logs to S3 (Athena on demand).
- Outputs: VPC ID, subnet IDs, SG IDs, endpoint DNS.

## Acceptance
`aws ec2 describe-vpc-endpoints` lists all 14. cfn-nag clean.

## Enhancements (v2.1)
- **Cost switch:** parameters `NatStrategy` (per-az | single | none) and `EndpointProfile`
  (full | minimal). 3× NAT + 12 interface endpoints ≈ $200+/month before a single task runs —
  DEV/sandbox should run single-NAT + minimal endpoints; PROD runs the full posture. (See the
  budget note in 9.2.)
- Outputs written to SSM `/platform/{env}/network/*` instead of Exports (deletion-friendly,
  consistent with 6.6's stated approach).
- CIDR is a parameter with the /16 as default — multi-env accounts need non-overlapping ranges.
