# Prompt: Per-template Execution Role Pattern

## Goal
Produce a reusable pattern for per-template execution roles.

## Constraints
- `infrastructure/platform/roles/exec-role-template.yaml`, parameterised: TemplateId,
  AllowedActions (CSV), AllowedResources.
- Trust: only platform-worker-task-role, condition `sts:ExternalId = template-{TemplateId}`.
- Managed via nested stacks from a parent `roles-registry` stack; publishing a template → CI
  applies the registry update.
- cfn-nag: no wildcard Resource except iam:PassRole to service-linked roles.

## Acceptance
Publishing the s3-bucket template creates exec-role-s3-bucket with S3-only permissions.

## Enhancements (v2.1)
- Every generated role attaches the `platform-execution-boundary` permissions boundary (3.6) —
  a template author granting themselves `iam:*` in AllowedActions is still capped.
- Registry stack emits a drift alarm: a role modified outside CFN (console edit) pages platform-warn.
- ExternalId derivation documented and validated by the worker before AssumeRole — mismatch is a
  terminal, alertable error, not a retry.
