# Prompt: OIDC Federation Setup

## Goal
Wire OIDC federation between GitHub Actions and AWS so workflows assume roles without long-lived keys.

## Constraints
- OIDC provider deployed by bootstrap/quickstart (6.1 / 10.x).
- One role per environment + purpose: gh-plan-role (read-only, PR workflows); gh-deploy-dev-role
  (main only); gh-deploy-stg-role (after dev green); gh-deploy-prod-role (manual environment
  approval); gh-templates-sync-role (platform-templates repo).
- Trust: `token.actions.githubusercontent.com:sub` with exact repo + branch matching.
- Workflows use `aws-actions/configure-aws-credentials@v4` with role-to-assume.
- Session name `{actor}-{run_id}` for CloudTrail traceability.

## Acceptance
Workflow logs show the assumed role. CloudTrail shows AssumeRoleWithWebIdentity with the correct
token subject.

## Enhancements (v2.1)
- Every trust policy also pins `aud: sts.amazonaws.com` — sub-only conditions are a known
  misconfiguration class.
- stg/prod deploy roles additionally condition on
  `token.actions.githubusercontent.com:environment` (platform-stg / platform-prod) so only jobs
  running inside the protected environment can assume them — the environment gate becomes an IAM
  fact, not just a UI fact.
- A scheduled job asserts no IAM users with access keys exist in platform accounts (the
  "no long-lived keys" rule, continuously verified).
