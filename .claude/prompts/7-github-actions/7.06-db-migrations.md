# Prompt: DB Migrations Workflow

## Goal
Produce `.github/workflows/migrations.yaml` — Flyway migrations against target Aurora before the
compute deploy.

## Constraints
- Triggered by the deploy workflow as a job before the compute stack.
- Runs a Fargate task with the flyway image; `flyway migrate`. Credentials via Secrets Manager
  (GetSecretValue by task role).
- `baseline-on-migrate=false`; fail loudly if baseline needed.
- Metrics: platform_db_migration_duration_seconds, platform_db_migration_success.
- Dry-run (`flyway info`) via workflow_dispatch input.
- Rollback strategy documented: Flyway forward-fix only.

## Acceptance
A new migration merged to main is applied to dev. A failed migration halts deploy without
touching compute.

## Enhancements (v2.1)
- Expand/contract policy stated as a rule: migrations must be backward-compatible with the
  currently-running app version (N-1), because migrate runs before compute — destructive column
  drops happen one release after code stops reading them.
- The workflow tails the Fargate task's log stream into the Actions log — a silent hung migration
  is the worst debugging experience otherwise.
- Advisory: wrap migrate in a `flyway lock`-equivalent via the 3.10 lock (`db-migrate` lock name)
  so parallel envs/hotfixes can't interleave.
