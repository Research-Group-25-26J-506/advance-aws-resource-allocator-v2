# Prompt: Rollback Workflow

## Goal
Produce `.github/workflows/rollback.yaml` — manual workflow to roll back a deploy.

## Constraints
- workflow_dispatch inputs: environment, target_git_sha.
- Steps: (1) verify the SHA has valid images in ECR; (2) point ECS services at images tagged
  target_git_sha; (3) skip DB — Flyway forward-fix only; (4) create an incident record in the
  incidents table; (5) Slack + PagerDuty notify.
- Runbook link in the workflow description. Executable only by platform-leads (environment
  reviewers).

## Acceptance
Emergency rollback within 5 minutes. The rollback is visible in the incidents table.

## Enhancements (v2.1)
- Step 0: compare target SHA's applied migrations against current DB (flyway info diff) and
  hard-warn when rolling back across a migration boundary — "skip DB" is only safe under the 7.6
  expand/contract rule; make the check explicit.
- Rollback updates `/platform/{env}/deployed-sha` and drops a Grafana annotation, same as deploys —
  dashboards must not lie during incidents.
- A quarterly game-day exercises this workflow in stg; an untested rollback path is a rumor.
