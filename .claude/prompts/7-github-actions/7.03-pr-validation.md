# Prompt: PR Validation Workflow

## Goal
Produce `.github/workflows/pr-validation.yaml` — runs on every PR against main.

## Constraints
- Trigger: pull_request → main. Concurrency group `pr-{number}`, cancel-in-progress.
- Parallel jobs: frontend-lint (pnpm lint/typecheck/test); backend-build (gradle build, test
  reports, junit + jacoco upload); backend-integration (Testcontainers); cfn-validate (cfn-lint +
  cfn-nag strict on infrastructure/); openapi-spec (spectral); security-scan (trivy fs, SARIF
  upload); workflow-lint (actionlint); templates-lint (local-validate on modified templates).
- Results as PR checks; block merge on failure. Aggressive gradle + pnpm caching.
- Total runtime target < 8 minutes.

## Acceptance
A PR opens a set of green checks. A failing check clearly indicates why in the PR UI.

## Enhancements (v2.1)
- Path filters: frontend jobs skip on backend-only diffs and vice versa (with a required
  "skipped = success" summary job so branch protection still passes) — the 8-minute target is
  unreachable otherwise.
- `permissions:` block per job, least privilege (security-scan needs `security-events: write`,
  nothing else does).
- Fork-PR safety: no secrets in this workflow; anything needing secrets runs on
  pull_request_target with an explicit checkout-of-base pattern, or not at all.
