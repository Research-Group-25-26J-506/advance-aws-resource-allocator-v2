# Prompt: Repo→S3 Sync Lambda

## Context
The quickstart's sync Lambda is dual-mode: it runs as a **CloudFormation Custom Resource** during
stack create/update (seeding the bucket) and as a **scheduled EventBridge target** afterwards
(keeping the bucket following the repo until the full platform sync service — 3.9 — takes over).

## Goal
Implement (or extend) the inline Python 3.12 sync Lambda used by `platform-quickstart.yaml`.

## Constraints
- Detect mode by `ResponseURL` in the event: present → custom-resource mode (must always call
  cfnresponse, success or failure); absent → scheduled mode (read config from env vars).
- Download `https://codeload.github.com/{org}/{repo}/tar.gz/refs/heads/{branch}`; for private
  repos, resolve a token from the Secrets Manager ARN (secret may be plain string or JSON with a
  `token` key) and send it as a Bearer header. Never log the token.
- Extract in-memory; upload only regular files under `TemplatesPathPrefix`, stripping the prefix
  so S3 keys are `{templateId}/{version}/{file}` — exactly the layout the platform expects.
- Safety guards: skip entries with `..` or absolute paths; skip non-files (symlinks, dirs);
  bound total processed size; 5-minute Lambda timeout, 512 MB memory.
- On Delete events: succeed without touching the bucket (retention is the bucket's job).
- Return/emit the number of objects synced (custom-resource Data + structured log line).
- **The bucket is versioned**, so repeated syncs of identical content simply create new versions —
  acceptable for the quickstart; the full platform sync (3.9) adds immutability enforcement,
  validation, and DB registration on top.

## Acceptance
- Stack create against a public repo seeds the bucket; against a private repo with a valid secret
  ARN it also seeds; with a bad token the stack **fails** with a readable reason.
- Scheduled invocation logs `{"synced": N, "bucket": ...}` and updates changed files.
- A tarball entry containing `../` is skipped, never written.

## Enhancements over a naive implementation
- ETag/short-circuit option: store last-synced commit SHA in SSM and skip upload when unchanged
  (GitHub `HEAD` via API) — keeps the hourly schedule free.
- Optional SNS topic parameter for sync-failure notifications before the full observability stack
  exists.
- This Lambda is deliberately **not** the production sync path: it does no validation. Document
  the handover: once 3.9/5.x are live, disable the schedule (parameter flip) and let the platform
  own publishing.
