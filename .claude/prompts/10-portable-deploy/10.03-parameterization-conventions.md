# Prompt: Portability Conventions (make every stack account-agnostic)

## Goal
Produce `docs/portability.md` + apply these conventions across all CFN in Section 6.

## Constraints (the conventions)
1. **No hardcoded identity.** Account IDs, regions, partition (`aws` vs `aws-cn`/`aws-us-gov`)
   always via pseudo-parameters. Bucket names: `platform-{purpose}-${AWS::AccountId}-{env}`.
2. **`EnvironmentName` parameter on every stack**, used in names, tags, and SSM paths.
3. **SSM Parameter Store is the wiring layer.** Producers write
   `/platform/{env}/{stack}/{key}`; consumers use
   `AWS::SSM::Parameter::Value<String>` parameter types or dynamic references. **Never
   CloudFormation Exports** (they make teardown and refactors painful).
4. **The quickstart (10.1) is the only manual step.** Every other stack must deploy from a fresh
   account given quickstart's SSM parameters + CI roles.
5. **Cost profiles are parameters, not forks:** `NatStrategy`, `DbTier`, `Scale`,
   `ObservabilityProfile` (see 6.2/6.3/6.4/6.6) — the same templates serve a $50/month sandbox
   and a production account.
6. **Idempotent apply:** every deploy script uses `aws cloudformation deploy`
   (`--no-fail-on-empty-changeset`); running it twice is always safe.
7. A **conformance CI check** greps `infrastructure/` for 12-digit account IDs, hardcoded
   `arn:aws:` region/account segments, and `Fn::ImportValue`, and fails the PR on any hit.

## Outputs
`docs/portability.md` + the CI conformance check + a canonical SSM key registry
(`docs/ssm-keys.md`) listing every published parameter.

## Acceptance
Deploying the entire platform into a brand-new account requires: (1) quickstart stack,
(2) setting three GitHub environment variables (account id, region, role ARN), (3) merging to
main. Nothing else.
