# Prompt: Quickstart Stack (single CFT, any account)

## Context
The platform must be **pluggable**: someone with a fresh AWS account uploads ONE CloudFormation
template through the console (genuinely drag-and-drop), fills in parameters, and ends up with
everything the rest of the platform needs to bolt on — including an S3 template registry that is
**already seeded from, and kept in sync with, the platform-templates GitHub repo**.

## Goal
Produce `quickstart/platform-quickstart.yaml` — a single, dependency-free CloudFormation template.

## Inputs (parameters)
- `EnvironmentName` (dev|stg|prod), `GitHubOrg`, `TemplatesRepo` (default platform-templates),
  `TemplatesBranch` (default main), `TemplatesPathPrefix` (default `templates/`).
- `GitHubTokenSecretArn` (optional — blank for public repos).
- `EnableScheduledSync` (default true) + `SyncScheduleExpression` (default rate(1 hour)).
- `EnableGitHubOidc` (default true) + `PlatformRepo` (org/repo allowed to assume CI roles).
- `SyncNonce` — change on stack update to force an immediate re-sync.

## Constraints
- **No pre-existing resources required.** Deployable via console upload or one
  `aws cloudformation deploy` command.
- Creates: versioned + encrypted + BPA'd templates bucket named
  `platform-templates-{AccountId}-{env}`; a sync Lambda (inline code — no artifact bucket
  chicken-and-egg); a Custom Resource that runs the first repo→S3 sync during stack creation;
  an optional EventBridge schedule re-running the sync; optionally the GitHub OIDC provider +
  `platform-ci-deploy-{env}` / `platform-ci-plan-{env}` roles.
- **Publishes every output to SSM** under `/platform/{env}/...` (templates-bucket, sync-fn arn,
  role ARNs) — downstream stacks discover resources by convention, never by hardcoding.
- Stack CREATE must **fail** if the initial sync fails (bad org/repo/token surfaces immediately,
  not at first use).
- cfn-lint clean. Bucket policy denies non-TLS. Sync Lambda's role is scoped to this bucket (and
  the one optional secret) only.
- Teardown-friendly: bucket uses `DeletionPolicy: Retain` (versioned buckets can't be deleted
  non-empty); document emptying + deletion in 10.04.

## Outputs
`quickstart/platform-quickstart.yaml` + `quickstart/README.md` (console + CLI instructions,
parameter table, verification commands, troubleshooting).

## Acceptance
- Fresh AWS account + console upload + defaults + a public templates repo → CREATE_COMPLETE, and
  `aws s3 ls` on the new bucket shows the repo's `templates/` tree.
- Changing `SyncNonce` and updating the stack re-syncs.
- With `EnableGitHubOidc=true`, a GitHub Actions workflow in `PlatformRepo` assumes the deploy
  role via OIDC.
- Deleting the stack leaves the bucket (retained) and removes everything else cleanly.

## Notes
A working reference implementation ships in `/quickstart/platform-quickstart.yaml` in this pack —
use this prompt to extend or regenerate it, and keep the acceptance list green.
